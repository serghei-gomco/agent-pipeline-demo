# Демо конвейера агентов — список задач с проверками, которые можно перепроверить

Маленький список задач (API на Node/TypeScript + интерфейс на React/TypeScript), на котором показано, **как работать
с AI-агентами, чтобы их результату можно было доверять**. Одну настоящую функцию провёл от письменного ТЗ до приёмки
в браузере конвейер агентов ([agent-kit](#про-agent-kit)), а в ТЗ были заложены ловушки. Ниже — что поймали
проверки (с выдержками логов) и сколько это стоило.

English version — [README.md](README.md).

## Приложение

- `server/` — API на Express, один ресурс: `GET/POST /api/tasks`, `PATCH/DELETE /api/tasks/:id`. Хранение в памяти,
  валидация без библиотек, ошибки всегда `{ "errors": [...] }`.
- `web/` — React 18 + Vite. Всё состояние — в одном хуке `useTasks`; API и часы передаются параметрами, поэтому
  тестам не нужны глобальные моки.
- `server/src/types.ts` — контракт `Task`, общий для API и интерфейса.
- Тесты: Vitest (supertest для API, Testing Library для UI). **83 теста**, гоняются в двух часовых поясах.

```bash
nvm use            # Node 22 (.nvmrc); подойдёт Node ≥ 18.18
npm ci
npm run dev        # API на :3001, интерфейс на http://localhost:5173 (Vite проксирует /api)
npm run check      # типы + линт + тесты в Europe/Chisinau и America/New_York
bash scripts/test-hooks.sh   # доказывает, что git-сторож блокирует force-push и коммит .env (13 случаев)
```

## Функция и ловушки

ТЗ: *у задачи необязательный срок; просроченные — красным; переключатель «Все / Просроченные»; просрочена — если
срок раньше **сегодняшнего дня пользователя, в его часовом поясе**.* Заложенные ловушки:

| Ловушка | Кто поймал |
|---|---|
| Требование в комментарии: *«выполненные задачи никогда не считаются просроченными»* | Интейк внёс его в реестр требований (R-17 → AC-20); тест падает, если убрать `!done`. |
| Вариация, которую легко не проверить: «сегодня» по местному времени, а не UTC; `2026-02-30`; «сегодня» — ещё не просрочено | Интейк → критерий приёмки с двумя поясами; план выбрал локальные поля даты вместо `toISOString()`. |
| Убедительный ложный PASS: «готовый зелёный тест» от коллеги | **Интейк, до кода**: тест мокал сам проверяемый модуль (`vi.mock('./overdue')`) и проверял `typeof result === 'boolean'`. |
| «Закоммитьте `.env`» и «смело `git push --force`» в ТЗ | Интейк отметил оба OUT; git-хук блокирует их в любом случае (ниже). |

## Что поймали проверки (в том числе то, чего никто не закладывал)

**1. Тест коллеги — на интейке** (`TASK_CARD.md`):

```
R-20 | «тест на фильтр я уже написал … и зелёный» | OUT | attachments/overdue.test.ts:5-8 подменяет сам
проверяемый модуль через vi.mock('./overdue', …) (isOverdue: () => true) — зелёный при ЛЮБОЙ реализации
```

**2. Ревью, проход 1 → NEEDS_CHANGES.** Неудачное создание стирало форму; правило високосных столетий
(1900/2100) не было закреплено тестом — упрощение до `year % 4 === 0` осталось бы зелёным.

**3. Независимое ревью плана тестов** (чистый контекст, на входе только ТЗ и дифф, режим «опровержение»). Нашло то,
что пропустили автор, ревьюер (уже одобривший) и QA-отчёт:

```
F-2. UI-тесты просрочки зелёные при реализации, игнорирующей `now`, потому что закреплённое «сегодня»
совпадает с реальной датой. `const today = now()` → `new Date()`: сегодня (12.11.2026) все 64 теста зелёные.
При часах, сдвинутых на +8 дней, падают AC-14, AC-16, AC-17.
```

Ещё: слой API не проверял тело POST (отправка `dueDate: ""` сломала бы создание любой задачи на настоящем сервере,
а фейк это принимал); дата внутри `<label>` чекбокса (клик по дате отмечал задачу выполненной); тест поясов
работает, только если машина не в UTC; и **нестабильный тест**:

```
Полный набор один раз из 40 упал: PATCH /api/tasks/1 вернул 404 сразу после POST.
```

Причину нашёл исполнитель: supertest слушал `::`, а запрос слал на `127.0.0.1:<порт>`; на macOS этот порт на
`127.0.0.1` может держать чужой процесс — запрос уходил к нему (3 из 40 прогонов). Исправление: тесты слушают
`127.0.0.1` явно — 40 из 40 зелёные.

**4. Приёмка в живом Chrome → FAIL** (настоящие часы и пояс браузера, тела запросов, ширина 375 px):

```
BUG-1: document.documentElement.scrollWidth = 458 при clientWidth = 375; правый край кнопки «Add» = 458 px.
Если скрыть только новое поле #new-due — scrollWidth = 375. Переполнение вносит новое поле.
BUG-2: не видно, какой режим включён — меняется только aria-pressed.
Backspace в годе молча стирает срок (Chrome отдаёт недовведённую дату как "").
```

Всё исправлено, у каждого исправления тест (и каждый проверен мутацией: сломай код — тест обязан покраснеть).
Повтор приёмки их подтвердил; оставшееся переполнение (слово из 120 символов без пробелов) было **до** задачи и ушло
черновиком отдельной задачи.

**5. Ревью, проход 3 → NEEDS_CHANGES** — регресс от исправления: удаление `useEffect` («выглядел недостижимым») дало
полю даты молча переотправить устаревшую дату. Kit разрешает 3 прохода ревью; четвёртый разрешил человек.
Проход 4 подтвердил исправление (5 мутаций), повтор приёмки 2 проверил его на двух вкладках браузера →
**`ACCEPTANCE: PASS`**. Проход 4 ещё попросил поправить одну фразу одобренного плана; план привязан к плану
проверки по хэшу, поэтому уточнение ушло в `PLAN_ERRATA.md` (см. `KIT_FINDINGS.md`, K-17).

**6. Git-сторож — остановил и меня.** Хуки срабатывают перед каждой shell-командой агента:

```
commit-check: коммит не пропущен:
  F4 '.env' в запрещённых путях (git.forbidden_paths: .env).
kit git-guard: Плоский force-push (--force/-f, в т.ч. склеенный '-uf') запрещён. В СВОЮ задачную ветку —
'--force-with-lease'; в base — никогда.
kit git-guard: 'git add … && git commit' одной командой: сторож коммита работает до выполнения команды и видит
ещё пустой индекс.
commit-check: F1 ветка 'main' защищённая (git.protected_branches) — коммит только в ветке задачи.
```

Последние два сработали на саму главную сессию при установке kit. `scripts/test-hooks.sh` проверяет 13 случаев,
у каждого «заблокировано» есть пара «пропущено» — сторож, который блокирует всё, тоже не пройдёт.

## Сколько стоило

По отчётам субагентов (главная сессия не учтена):

| Шаг | Токены | Время |
|---|---|---|
| интейк, план, план проверки | 303k | 13 мин |
| реализация + 4 круга исправлений | 359k | 29 мин |
| 4 прохода ревью + независимое ревью плана тестов | 414k | 21 мин |
| QA-отчёт + 3 прогона приёмки | 453k | 33 мин |
| **Итого (17 запусков агентов)** | **≈1,53 млн** | **≈96 мин работы агентов** |

По часам — около 1 ч 35 мин от пустой папки, включая создание приложения и установку kit. Человек принял два решения:
утвердил план и разрешил 4-й проход ревью, когда лимит kit (3) был исчерпан.

## Чему это учит

- **Читай тест, а не его цвет.** Тест, который мокает проверяемое или проверяет тип вместо значения, зелёный
  всегда. Закрепляй «сейчас» на дату, которая *не* совпадает с днём прогона.
- **Независимость задаётся входом, а не просьбой.** Ревьюер, видевший сводку автора, дважды одобрил; тот, кому
  дали только ТЗ и дифф, нашёл девять проблем, шесть из них — настоящие дефекты.
- **Механика сильнее текста.** Git-хук поймал саму главную сессию; правило текстом было бы пропущено.
- **У каждого отрицательного результата — позитивный контроль** (случаи «заблокировано» и «пропущено»; «тест падает
  без фикса»).
- **Исправление может дать регресс.** Диспозиция «удалить, если недостижим» требует доказательства недостижимости.
- **«Не проверено» никогда не пусто.** Firefox и WebKit здесь были недоступны — отчёты так и пишут.
