## Находки

### F-1 Неудачное создание стирает введённые название и срок
- где: `web/src/App.tsx:19-21` (вместе с `web/src/useTasks.ts:24-32`)
- сценарий поломки: ввести название «Pay rent» и срок `2026-12-01` → «Add» → `api.create` отвечает ошибкой
  (сеть, 400). `run` в `useTasks` ошибку перехватывает и не пробрасывает, поэтому `await add(...)` завершается
  успешно и выполняются `setTitle('')` и `setDueDate('')`. Пользователь видит алерт и пустую форму — оба поля
  надо вводить заново. Подтверждено прогоном вне репозитория: после ошибки `title=""`, `due=""`.
  Для названия поведение было и до диффа; дифф распространил его на новое поле (строка `setDueDate('')` новая),
  и теперь теряется ввод из двух полей. Теста на этот путь нет: `App.test.tsx:72` («shows an API error») значения
  полей после ошибки не проверяет, новые тесты AC-10 покрывают только успех.
- что нарушено: ось `qa.axes` «ошибка API (4xx, сеть) — что видит пользователь» для нового поля; п.6 порядка
  ревью — путь отказа зависимости без теста. AC-10 требует очистки «после добавления», а не после отказа.
- диспозиция: FIX — `add` (через `run`) возвращает признак успеха, форма очищает оба поля только при успехе;
  тест: `failCreate` + заполненные название и срок → алерт виден, оба поля сохранили значения.

### F-2 После неудачного сохранения срока ошибка исчезает, а в строке остаются две разные даты

  алерт, в поле `2027-01-15`, в тексте `2026-12-01` (это принято планом). Дальше отметить эту или любую другую
  задачу выполненной → `run` сбрасывает ошибку. Итог: алерта нет, в поле даты `2027-01-15`, рядом с названием
  `2026-12-01`, на сервере `2026-12-01`. Ничто не говорит пользователю, что поле не сохранено. Подтверждено
  прогоном вне репозитория: `alert=null input=2027-01-15 time=2026-12-01`.
- что нарушено: ось «ошибка API — что видит пользователь». План («Риски и откат», ось «ошибка API») принял
  расхождение поля и текста только вместе с видимым алертом; состояние без алерта планом не рассмотрено и
  тестом AC-12 (`App.test.tsx:133`) не покрыто.
- диспозиция: DEFER

    ошибку у строки, пока поле отличается от сохранённого), а «черновик остаётся в поле» — решение плана,
    принятое на гейте; менять его без человека нельзя.
