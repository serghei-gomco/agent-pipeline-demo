## 1. Несохранённый срок в строке после ошибки остаётся без пометки (F-2)

- что: после неудачного PATCH срока поле даты хранит несохранённое значение, а алерт сбрасывается первым же
  следующим действием; в строке видны две разные даты без объяснения.
- где: `web/src/App.tsx:101-122` (`DueDateInput`), `web/src/useTasks.ts:27` (`setError(null)`) — строки на `59dd52f`.
- дополнение (проход 3): после правки TF-4 в поле может остаться и недовведённая дата (уход из поля её не
  сохраняет и не сбрасывает); в форме создания устаревшая ошибка сервера остаётся рядом с новой подсказкой про
  неполную дату (`web/src/App.tsx:22-25`, REVIEW F-8) — тот же выбор поведения.
- дополнение (проход 4, REVIEW F-11): два сохранения в пути — ввели X, ушли из поля, ввели Y, ушли; ответ на первое
  ставит в поле X поверх Y (`web/src/App.tsx:114-116`, флаг `edited` снят в `onBlur` `:121` до ответа сервера). Если
  второе сохранение упало — введённое Y из поля пропало (AC-12 в этой гонке). Вариант правки: не синхронизировать
  черновик, пока свой запрос в пути (счётчик), + тест с двумя отложенными ответами, второй — отказ.
- почему не FIX-HERE: нужен выбор поведения (вернуть прежний срок в поле при ошибке или показывать ошибку у
  строки), а «черновик остаётся в поле» — решение плана, принятое на гейте.
- оценка: малая — один компонент и один тест.
- когда вернуться: приёмка на живой сборке с остановленным API либо первая жалоба «срок не сохранился».
