# BUG-3 — название из 120 символов без пробелов распирает строку списка: горизонтальная прокрутка на 1280 и 375 px

- Кейс: QC-69 (AC-13; ось «пустые и граничные данные»: длинное название, ширина 1280/375)
- Sha HEAD: 8ee52835eca1aa685a91a100a0d7447bc22b7b6b, ветка `feat/T-20261112-1-due-dates`
- Браузер: Google Chrome 157.0.8103.51 (headless, Playwright 1.66 `channel: 'chrome'`)
- Происхождение: вынесено из «попутных» наблюдений BUG-1 (круг r1, первый прогон). Само переполнение было и до задачи;
  задача добавляет к нему ширину поля даты и `<time>` (~125 px). Решение «чинить в этой задаче или вынести» — за человеком.

## Шаги воспроизведения

1. `bash scripts/node.sh npm run dev`; через API создать задачу с названием из 120 символов без пробелов
   (`'L'.repeat(60) + 'ДлинноеНазвание'.repeat(4)`, обрезано до 120) и сроком `2026-11-13`.
2. Открыть `http://localhost:5173` в окне 375×800, затем 1280×800.

## Ожидаемо (QA_PLAN, QC-69)

Поле даты и кнопка «×» не уезжают за экран; горизонтальной прокрутки страницы нет.

## Фактически

- 375 px: `scrollWidth` = **1252** при `clientWidth` = 375; поле даты и «×» строки — за правым краем.
- 1280 px: `scrollWidth` = **1596** при 1280; то же.
- Если скрыть элементы, добавленные задачей (поле даты строки и `<time>`): 1127 / 1471 — переполнение остаётся,
  т.е. причина — отсутствие переноса длинных слов в `.title` (в CSS нет `overflow-wrap`/`min-width: 0`), а не новое поле.
- Названия с пробелами, кириллица и эмодзи — без переполнения на обеих ширинах; форма создания на 375 — в экране (BUG-1 исправлен).
