# BUG-1 — на ширине 375 px новое поле даты в форме создания выталкивает «Add» за экран (горизонтальная прокрутка)

- Кейс: QC-69 (AC-13; ось «пустые и граничные данные»: длинное название, юникод, ширина 375)
- Sha HEAD: 7127f317b93b9f8dfa283d934418176b352fac99, ветка `feat/T-20261112-1-due-dates`
- Браузер: Google Chrome 157.0.8103.51 (headless, Playwright 1.66 `channel: 'chrome'`), локаль поля даты из ОС — `дд.мм.гггг`

## Шаги воспроизведения

1. `bash scripts/node.sh npm run dev`, открыть `http://localhost:5173` в окне шириной 375 px (viewport 375×800).
2. Список может быть пустым: дефект виден уже в форме создания.
3. Посмотреть на строку формы «New task [ ] Due date [дд.мм.гггг] Add».

## Ожидаемо (QA_PLAN, QC-69)

Поле даты и кнопки не уходят за экран, горизонтальной прокрутки у страницы нет.

## Фактически

- `document.documentElement.scrollWidth` = **458** при `clientWidth` = 375; правый край кнопки «Add» = 458 px.
- Если скрыть только новое поле `#new-due` с подписью (т.е. форма как до задачи), `scrollWidth` = 375, правый край «Add» = 359 —
  переполнение вносит именно новое поле.
- Попутно (тот же кейс, тот же снимок): на 375 px дата рядом с длинным названием переносится по дефису на две строки
  («2026-» / «11-13») — у `<time class="due">` нет запрета переноса.
- Попутно (не регрессия задачи): название из 120 символов без пробелов переполняет строку и при 1280, и при 375
  (`scrollWidth` 1650 / 1306); без новых элементов строки — 1471 / 1127, т.е. переполнение было и до задачи
  (в CSS нет переноса длинных слов), новые поле даты и `<time>` добавляют ~180 px. Названия с пробелами,
  кириллица и эмодзи при 1280 — без переполнения.
