# /kit-task — конвейер задачи

Ты — главная сессия. Агенты делают работу, ты держишь гейты, читаешь маркеры и ведёшь `STATE.md`.
Источник истины по маркерам и порядку — `docs/CONVENTIONS.md` kit (п. 3–4) и `rules/pipeline.md`.

## 0. Подготовка

1. Нет `.agent-kit.yml` в корне проекта — стоп: «kit не настроен, скопируй agent-kit.example.yml».
2. Ключ: от человека или по `tracker.key_pattern`; трекера нет — `T-<yyyymmdd>-<n>`. Слаг — 2–4 слова латиницей.
3. `bash .claude/kit/scripts/task_new.sh <KEY> <slug>` — создаёт `<tasks.dir>/<KEY>-<slug>/`.
4. В `TASK.md` — ТЗ дословно, комментарии, вложения (файлы — в папку задачи, ссылки — списком).
   Нет доступа к вложению — строка «не получено: …», не пропуск.

## 1. Цепочка и переходы

| Шаг | Агент | Дальше АВТО, если | СТОП, если |
|---|---|---|---|
| 1 | `kit-intake` | `QUESTIONS: none` и `NEXT_AGENT: kit-planner` | маркера нет; `QUESTIONS: n` → показать вопросы с вариантами по умолчанию; `NEXT_AGENT: STOP`; `NEXT_AGENT: kit-implementer` → показать карточку и спросить «делаем без плана? (да/нет)» |
| 2 | `kit-planner` | — (дальше всегда человек) | `PLAN: blocked`; маркера нет |
| ⛔ | **гейт плана** | — | всегда ручной, см. п. 2 |
| 3 | `kit-qa-planner` | `QA_PLAN: written` → implementer | `blocked`; маркера нет |
| 4 | `kit-implementer` | `NEXT_AGENT: kit-reviewer` | `STOP (…)` — показать раздел «Расхождение» CHANGES.md |
| 5 | `kit-reviewer` | `VERDICT: APPROVED` | `NEEDS_CHANGES` / `BLOCKED` |
| 6 | `kit-qa-report` | `GATES_AFTER_QA: ok` | `✗`; нет `ACCEPTANCE_RUN` |
| 7 | `kit-acceptance` | `ACCEPTANCE: PASS` → предложить /kit-deliver | `FAIL` / `BLOCKED` |

- Автопереход объявляй одной строкой («kit-reviewer: APPROVED → запускаю kit-qa-report») и не жди «да».
  При `pipeline.auto_chain: false` — вместо объявления вопрос «запустить <агент>? (да/нет)».
- Маркер читается по первому слову значения: `APPROVED` / `PASS` / `ok` — принят, всё остальное — нет.
  Маркера нет или он не по контракту — СТОП и показать хвост ответа агента. Молчание не согласие.
- В промт агенту — путь папки задачи, круг, строки-флаги (`COMMIT_MODE: …`, `QA_PLAN: <путь>`), и
  только то, что ему нужно. Сводки других агентов в промт не пересказывай.

## 2. Гейт плана

Показать человеку ТОЛЬКО блок «## Для человека» из `PLAN.md` дословно и одну строку:
«План принимаешь? (да / правка: …)». Без пересказа шагов и без других вопросов в том же сообщении.
- «правка: …» → `kit-planner` правит → блок показывается заново.
- «да» → `QA_PLAN_REQUIRED: yes` (или риск из `pipeline.qa_plan_risk`, или круг возврата) →
  `kit-qa-planner`; иначе сразу `kit-implementer`. Если в QA_PLAN «Ревью плана проверки: требуется» —
  запусти независимого ревьюера (п. 4) до implementer'а.
- Перед implementer'ом: `python3 .claude/kit/scripts/check_gates.py --stage plan <task_dir>` без ✗.
- При `git.worktrees: true` воркtree задачи должен существовать; создать его — обратимо и локально,
  делается без вопроса (от `<remote>/<base_branch>`, без upstream на базу).

## 3. Цикл исправлений

`NEEDS_CHANGES` ревью, FAIL приёмки или ✗ гейта → показать находки/баги одной сводкой. Находки с
диспозицией FIX чинятся тем же кругом (FIX-HERE): `kit-implementer` с промтом «исправить F-n / BUG-n,
план не менять», затем снова ревью. Не больше `pipeline.max_review_passes` проходов ревью по одному
артефакту — дальше стоп и показать человеку. После FAIL приёмки — повтор `kit-acceptance` по кейсам
багов (`--cases`) и регрессу.

## 4. Ревью плана тестов (`TEST_PLAN_REVIEW: required`)

Независимый агент (`kit-reviewer` или general-purpose) в чистом контексте. Первый абзац промта —
дословно из `rules/adversarial-review.md`. Вход: `TASK.md`, реестр R-n и AC из карточки, дифф от
merge-base. НЕ передавать: `QA_REPORT.md`, `CHANGES.md`, `STATE.md`, вердикты. Вопрос ревьюеру: «какие
вариации и сценарии этот дифф обязан пройти?». Его список сверить с матрицей отчёта; таблицу
«находка → принято / контракт непонят / компромисс / шум» записать в раздел «Ревью плана тестов»
`QA_REPORT.md`. Принятое — новые кейсы (и правки кода обычным циклом).

## 5. STATE.md — после каждого шага

`<task_dir>/STATE.md`, перезаписывается целиком:
```
этап: <агент/гейт> — <итог маркера>
круг: r<N>   ветка: <имя>   воркtree: <путь|нет>
следующий шаг: <одна строка>
ждёт человека: <что | нет>
открыто: <несрочное, одной строкой каждое>
```

## 6. Конец

`ACCEPTANCE: PASS` или `ACCEPTANCE_RUN: not required` + `GATES_AFTER_QA: ok` → одна строка итога и
«сдаём через /kit-deliver?». Сам не пушишь, не открываешь PR и не пишешь в трекер.

## Никогда

Пропускать гейт плана; запускать агента после стоп-маркера; давать авто-агентам git-write кроме
коммита implementer'а; задавать человеку больше одного вопроса за ход вне гейта плана.
