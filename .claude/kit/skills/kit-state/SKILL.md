# /kit-state — состояние задачи

1. Определи аргумент: ключ задачи (по `tracker.key_pattern`) или путь к папке задачи. Не назван —
   возьми задачу из текущего воркtree/ветки или спроси одной строкой.
2. Запусти:
   ```
   python3 .claude/kit/scripts/state.py <KEY|task_dir>
   ```
3. Вывод покажи как есть, без пересказа и без таблиц сверху.
4. Ошибка скрипта (нет конфига, задача не найдена, скрипт отсутствует) — покажи сообщение дословно и
   одну строку, что проверить (`.agent-kit.yml`, `tasks.dir`, установлен ли kit в `.claude/kit/`).

Ничего не меняй: ни файлов, ни git, ни трекера. Если вывод расходится с `STATE.md` задачи — скажи об
этом одной строкой; источник истины — диск и git, `STATE.md` обновляет главная сессия.

## Что ожидать в выводе

Скрипт печатает (формат задаёт сам `state.py`, скилл его не переделывает):
- ключ, папку задачи, круг (`r1`, `r2`, …);
- пройденные шаги конвейера по наличию артефактов: карточка, план, план проверки, изменения, ревью,
  QA-отчёт, приёмка, MR_REVIEW;
- последние маркеры каждого шага и принят ли вердикт (по первому слову значения);
- ветку, воркtree, upstream, число коммитов от merge-base, незакоммиченные файлы;
- следующий шаг — одной строкой.

## После показа

- Если следующий шаг — агент конвейера, не запускай его сам: это решает `/kit-task` по маркерам или
  человек. Можно одной строкой предложить: «дальше — <шаг>, продолжить через /kit-task?».
- Если вывод показывает нарушение (upstream на базовую ветку, вердикт не принят, а артефакты
  следующих шагов уже есть) — назови это одной строкой первым, до остального.

Работает и из главного окна-диспетчера (`/kit-dispatch` вызывает тот же скрипт).
