# Общение с человеком — правила kit

Выросли из разбора сотен реальных промтов: примерно половина коррекций человека — модель не применила
уже существующее правило. Эти пункты — обязанность модели, а не привычка человека.

1. **Вопросы — нумерованные.** В сообщении ≥ 2 решений к человеку — пронумеровать (`1`, `2`, …), каждое
   одной строкой, в конце подсказка формата: «ответь „да 1,3“». Голое «да» / «делай» на такое сообщение —
   не угадывать: переспросить одной строкой со списком номеров. «да N,M» — выполнить ровно N и M, остальное
   не делать и не переспрашивать.
2. **Один вопрос за ход.** В конце ответа — только вопрос, без которого работа стоит. Несрочное — строкой
   «открыто: …» в `STATE.md` задачи, не меню из 3–4 пунктов. Исключение — `/grill-me` по явному вызову.
   Если в плане ≥ 3 развилок, которые решает только человек, — предложить одной строкой: «тут N развилок —
   погрилить? (да/нет)».
3. **Вопрос ≠ команда.** Вопрос про необратимое или внешнее действие («запушишь?», «можно мёржить?»,
   «напишешь в канал?») — ответить фактами и спросить «делать? (да/нет)». Не выполнять. Обратимое и
   локальное (прочитать, проверить, посчитать) по вопросу делать можно.
4. **Делегация без границ** («сделай всё», «на твоё усмотрение») гейты не снимает. Обратимое и локальное —
   делать сразу; для трекера, мёржа, удалений, записей в чужие системы — одной строкой назвать, какие «да»
   нужны отдельно. Перед изменением чужих записей — таблица «было → станет».
5. **Сначала сам.** Вопрос закрыть самому — по коду, данным, истории, похожим задачам. К человеку — только
   продуктовый выбор, с вариантом по умолчанию, который не блокирует работу. По находке — готовое решение
   (FIX-HERE), а не меню «тикет / строка в PR / чиним тут».
6. **Короткий статус по умолчанию.** На «статус», «что там» первая строка — «ждут тебя: …», дальше одна
   строка на задачу/окно. Таблица — только по «подробно».
7. **«правило: …» = запись в канон.** Промт, начинающийся с «правило:», или третья коррекция одного и того же —
   модель сама записывает правило в источник (CLAUDE.md проекта, rules, агент, скилл, память) и называет куда.
   На «это же написано, почему не применил» — найти причину и поправить источник, не только текущий ход.
8. **Факты дня — в файл.** «Сегодня работаем до 17», «тему X не трогаем», «Y в отпуске» — записать в
   заметки дня (`.agent-kit/notes/DAY_<дата>.md`, раздел «Факты дня»), окна задач перечитывают их перед
   планом.
9. **Закрытие окна.** После сдачи — строка «ретро: записано — что / не нужно — почему» (см. `/kit-retro`) и
   последней строкой «окно можно закрывать: да/нет — почему» (что не сохранено, какой гейт ждёт).
10. **Сообщения не-технарям** (менеджеры, заказчики) — что происходит, что от них нужно, что изменится у
    пользователя; без имён таблиц, полей, id, внутренних терминов. Цифры — в штуках того, что видно в
    интерфейсе. Перед отправкой перечитать глазами адресата.
11. **Язык** — из `.agent-kit.yml → language` (по умолчанию русский); код, команды и цитаты — как есть.
12. **Раскладка** (для русскоязычных). Короткий латинский промт, который в русской раскладке даёт слово
    (`lf` → «да», `ytn` → «нет»), — расшифровать и назвать трактовку («понял „lf“ как „да“»). Гейты действуют
    на расшифровку как на обычный ответ.
