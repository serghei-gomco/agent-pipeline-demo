# Гейты git — правила kit

Механика — `/kit-deliver`; сторож — `hooks/git-guard.sh` (разбор команды + проверка коммита).
Параметры (ветки, шаблоны сообщений, запрещённые пути) — `.agent-kit.yml → git.*`.

## Коммит — без «да», но через сторож
- Коммит на каждый завершённый шаг плана `S-n` и на каждом гейте (после ревью, после круга возврата);
  3–6 осмысленных коммитов на задачу, не «wip». Красный шаг (сборка/тесты падают) сливается со следующим.
- Сообщение — по `git.commit_pattern`; ключ задачи — если `git.require_task_key`; без AI-трейлеров, если
  `git.forbid_ai_trailers`. Заголовок ≤ 72 символов; при ≥ 3 файлах и ≥ 30 строках — тело «что было не так →
  что стало → чем проверено».
- `git add` — только явными путями. Фиксы — новыми коммитами. После коммита — `git show HEAD --stat`.

## Одно «да» на код
Ревью диффа от `git merge-base HEAD <remote>/<base_branch>` (коммиты + рабочее дерево) → пуш в свою ветку
(`git push -u <remote> <branch>`) → PR/MR. Каждый шаг показывать результатом, между ними не переспрашивать.
Нашла проверка проблему — СТОП внутри цепочки.

## Всегда отдельное «да» (в том же сообщении, от человека)
rebase, `--force-with-lease`, `reset --hard`, `cherry-pick`, `branch -D`, `commit --amend`, `merge <base>`
в свою ветку, `pull` (на базовой — только `--ff-only` при чистом дереве), любое действие с базовой веткой,
мёрж своего PR/MR (только по разовой явной просьбе и после проверки вслух: конфликты, отставание, сборка,
ревью, открытые вопросы). Порядок: проверка вслух (что теряется, где копия) → вопрос → «да» → команда.

## Никогда
`git push --force` / `-f`; `--no-verify`; пуш, мёрж или аппрув в `git.protected_branches`; аппрув чужого
PR/MR; `git add -A` / `.`; git-write или PR от автоматически запущенного агента (исполнитель только
коммитит свои шаги).

## Рабочее дерево
Если `git.worktrees: true` — код задачи только в отдельном воркtree от `<remote>/<base_branch>` с
`--no-track`; сразу после создания `git rev-parse --abbrev-ref --symbolic-full-name @{u}` обязан сказать
«no upstream configured». В общем чекауте ветку не переключать — там может работать другое окно.
Артефакты задачи (`tasks.dir`) — в основном чекауте, в коммиты не попадают.
