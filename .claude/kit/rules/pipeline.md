# Конвейер agent-kit — правила для главной сессии и агентов

Источник истины — `docs/CONVENTIONS.md` kit. Здесь — сжатая выжимка того, что нужно держать в
голове каждому окну. Всё проектное — из `.agent-kit.yml`; нет конфига — kit не работает, сказать.

## Конвейер

```
kit-intake → kit-planner → [гейт плана: человек] → kit-qa-planner (если риск) → kit-implementer
  → kit-reviewer (АВТО) → kit-qa-report (АВТО) → kit-acceptance (АВТО, если required) → /kit-deliver
```

Оркестратор — скилл `/kit-task`. Возврат — `/kit-reopen`. Сдача — `/kit-deliver`. Состояние —
`/kit-state`. Папка задачи — `<tasks.dir>/<KEY>-<slug>/`, круги — суффикс `-rN` у артефактов.

## Гейты

| Переход | Как |
|---|---|
| intake → planner | АВТО при `QUESTIONS: none` и `NEXT_AGENT: kit-planner` |
| planner → implementer | **ручной**: человеку только блок «## Для человека» + «План принимаешь? (да / правка: …)» |
| план одобрен → qa-planner | АВТО при `QA_PLAN_REQUIRED: yes` (риск из `pipeline.qa_plan_risk` или круг возврата) |
| implementer → reviewer | АВТО при `NEXT_AGENT: kit-reviewer` |
| reviewer → qa-report | АВТО при `VERDICT: APPROVED` |
| qa-report → acceptance | АВТО при `ACCEPTANCE_RUN: required` и `GATES_AFTER_QA: ok` |
| → сдача | ручные гейты `/kit-deliver`: «да» на код, «да» на трекер |

- Автопереход объявляется одной строкой и не ждёт «да» (при `pipeline.auto_chain: true`).
- Маркера нет, он не по контракту, или первое слово значения не `APPROVED` / `PASS` / `ok` — СТОП и
  показать человеку. Молчание не согласие.
- `VERDICT: NEEDS_CHANGES` / `BLOCKED`, `ACCEPTANCE: FAIL` / `BLOCKED`, `GATES_AFTER_QA: ✗` — СТОП.
- Проходов ревью — не больше `pipeline.max_review_passes` по одному артефакту.

## Git
Правила и сторож — `rules/git-gates.md` (коммит без «да» через сторож, одно «да» на код, отдельные «да», «никогда»).

## Трекер

Запись (комментарий, статус, новая задача) — только по «да» человека, если `tracker.write_requires_yes`.
Порядок — сначала комментарий, потом статус.

## Находки — FIX-HERE по умолчанию

- **FIX-HERE** — ≤ ~0.5 ч, та же область, без решения владельца → чинить тем же кругом.
- **TICKET** — > ~1 ч, другой модуль/владелец, продуктовый выбор, миграция данных прода → черновик в
  `FOLLOWUP_DRAFT.md` с «почему не FIX-HERE»; в трекер — только по «да». Однородные — одним черновиком.
- **NOTE** — мелочь (мёртвый код, комментарий) → строкой в описании PR.
Человеку не предлагать меню «тикет / строка / чиним» — предлагать готовое решение по этим правилам.

## Отчёты — честность

- «Не проверено» есть в каждом QA-отчёте и приёмке и никогда не пустая.
- Статусы кейсов: `PASS | FAIL | SKIPPED (причина) | INCONCLUSIVE`. Отрицательный результат без
  позитивного контроля тем же инструментом — `INCONCLUSIVE`.
- Каждая ось из `qa.axes` — кейсы или «н/п: причина»; голое «н/п» не принимается.
- Результат прогона пишется по факту запуска, не переписывается из чужой сводки.

## Браузеры — по признакам

По умолчанию один движок — первый из `qa.browsers`. Добавить второй и третий (WebKit/Safari,
Gecko/Firefox), если дифф или ТЗ задевает: вёрстку (CSS, flex/grid, sticky, шрифты, анимации, единицы
экрана); мобильную версию; формы, ввод, даты, медиа; cookie, хранилище, сторонние домены, iframe; или
браузер/устройство названы в ТЗ, или возврат найден не в браузере по умолчанию. Логика, данные, API,
тексты — один движок. В отчёте строка `БРАУЗЕРЫ: <набор> — <почему>`. Один браузер за раз; свою
сессию после прогона закрыть, чужую не трогать.

## Внешние стенды — минимум запросов

- Сколько запросов, столько кейсов. Запрещены циклы по страницам, краулеры, `--retry N`, частый опрос.
- Ожидание выката — по пайплайну CI, не опросом стенда.
- Первый ответ «доступ ограничен», 429 или 503 от защиты — ни одного повтора: стоп, BLOCKED, сказать
  человеку.
- Перед запуском своего сервера проверить, не занят ли порт чужим процессом; свой сервер после
  прогона остановить.
