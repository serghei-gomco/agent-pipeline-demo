# Соглашения agent-kit (единый контракт агентов, скиллов, хуков и гейтов)

Этот файл — источник истины для всех частей kit. Агент, скилл, хук или скрипт, который
расходится с ним, неправ; правится он, а не этот файл (кроме осознанной смены контракта).

## 1. Конфиг проекта — `.agent-kit.yml` в корне проекта

Всё, что зависит от проекта (язык, команды, ветки, трекер, оси вариаций), — только здесь.
Агенты и хуки kit не знают ничего о конкретном проекте и читают конфиг на шаге 0.
Читать конфиг из скрипта: `python3 .claude/kit/scripts/kit_config.py get <ключ.через.точку>`.
Полный перечень ключей с пояснениями — `agent-kit.example.yml`.

Важное:
- `commands.test | lint | build | run | typecheck` — команды проекта. Пустая строка = «в проекте нет».
  `{files}` в `lint` подставляется списком изменённых файлов.
- `git.base_branch` — от чего режутся ветки задач и куда идёт MR/PR.
- `git.protected_branches` — куда нельзя пушить напрямую никогда.
- `git.branch_pattern`, `git.commit_pattern` — регулярные выражения (Python `re`).
- `tracker.key_pattern` — как выглядит ключ задачи (`[A-Z]+-[0-9]+`, `#[0-9]+`, …).
- `tasks.dir` — где лежат папки задач (по умолчанию `.tasks`).
- `pipeline.*` — при каком риске обязательны план проверки, приёмка, ревью плана тестов.
- `qa.axes` — оси вариаций проекта; `qa.main_axis` — главная.

## 2. Папка задачи — `<tasks.dir>/<KEY>-<slug>/`

`KEY` — ключ задачи из трекера, либо `T-<yyyymmdd>-<n>`, если трекера нет.
Круги (возвраты): первый круг без суффикса, дальше `-r2`, `-r3` у артефактов круга (`PLAN-r2.md`).

| Файл | Кто пишет | Что это |
|---|---|---|
| `TASK.md` | человек / скилл `kit-task` | исходное ТЗ дословно + комментарии + вложения |
| `TASK_CARD.md` | `kit-intake` | карточка: реестр требований `R-n`, критерии `AC-n`, окружение, сложность |
| `PLAN.md` | `kit-planner` | план: блок «## Для человека», реестр, шаги `S-n`, карта двойников, матрица покрытия |
| `QA_PLAN.md` | `kit-qa-planner` | матрица вариаций и сценарии ДО кода (при триггере риска) |
| `CHANGES.md` | `kit-implementer` | что сделано по факту диффа, по шагам |
| `REVIEW.md` | `kit-reviewer` | находки с диспозициями, вердикт |
| `QA_REPORT.md` | `kit-qa-report` | покрытие требований, матрица, кейсы, «Не проверено», маркеры |
| `ACCEPTANCE.md` | `kit-acceptance` | прогон кейсов на живой сборке, доказательства, вердикт |
| `STATE.md` | главная сессия | где задача сейчас, следующий шаг, строки «открыто: …» |
| `FOLLOWUP_DRAFT.md` | ревьюер / главная сессия | черновики отдельных задач (TICKET) |
| `REOPEN_BRIEF-rN.md` | `kit-reopen` | класс возврата, риск, `NEXT: <одно действие>` |
| `MR_REVIEW[-rN].md` | `kit-mr-self-review` | первая строка `head: <sha>`, маркер `MR_SELF_REVIEW: APPROVED|NEEDS_CHANGES` |
| `bugs/BUG-n.md`, `evidence/QC-n.*` | `kit-acceptance` | дефект на файл; доказательства прогона |

На круге N ≥ 2 суффикс `-rN` у всех артефактов круга (`TASK_CARD-r2.md`, `REVIEW-r2.md` …).
Повторный проход ревью — разделом `## Проход K` в том же файле. Журналы проекта — `.agent-kit/`
в корне: `retro/RETRO_<дата>.md`, `notes/DAY_<дата>.md`.

## 3. Маркеры — последние строки итогового блока агента

Маркер — строка `ИМЯ: значение` в отдельной строке. Главная сессия и хуки читают только маркеры,
не прозу. Отсутствие маркера = СТОП и вопрос человеку (молчание не согласие).

| Агент | Маркеры |
|---|---|
| `kit-intake` | `QUESTIONS: none | <n>`, `COMPLEXITY: trivial|low|medium|high`, `RISK: low|medium|high`, `NEXT_AGENT: kit-planner | kit-implementer | STOP` |
| `kit-planner` | `PLAN: written <путь>`, `RISK: …`, `QA_PLAN_REQUIRED: yes|no` |
| `kit-qa-planner` | `QA_PLAN: written <путь> | blocked (<почему>)` |
| `kit-implementer` | `IMPLEMENTED: S-1..S-n`, `COMMITS: <n>`, `NEXT_AGENT: kit-reviewer` |
| `kit-reviewer` | `VERDICT: APPROVED | NEEDS_CHANGES | BLOCKED` |
| `kit-qa-report` | `ACCEPTANCE_RUN: required (<причина>) | not required (<причина>)`, `TEST_PLAN_REVIEW: required | not required (<причина>)`, `GATES_AFTER_QA: ok | ✗ <что>` |
| `kit-acceptance` | `ACCEPTANCE: PASS | FAIL | BLOCKED` (последняя строка `ACCEPTANCE.md`), строка `БРАУЗЕРЫ: <набор> — <почему>` |

Дополнительно: `TASK_CARD: written <путь>`, `PLAN: blocked (<почему>)`, `NEXT_AGENT: STOP (<причина>)` у
исполнителя при расхождении с планом, `REVIEW: written <путь>`, `VERDICT: BLOCKED (<причина>)`,
`QA_REPORT: written <путь>`.

Вердикт ревью: `APPROVED` — нет FIX и UPDATE-DOC, все DEFER оформлены; `NEEDS_CHANGES` — есть FIX или
UPDATE-DOC; `BLOCKED` — нет конфига/артефактов/диффа или нарушение `danger` требует решения человека.

Когда обязательно (любое из условий): план проверки — риск в `pipeline.qa_plan_risk` или круг возврата;
приёмка — риск в `pipeline.acceptance_risk`, круг возврата, дифф задевает `danger`; ревью плана тестов —
риск в `pipeline.test_plan_review_risk` или возврат; `/kit-mr-self-review` — риск в
`pipeline.mr_self_review_risk`, задет `danger` или возврат.

Вердикт «принят», только если ПЕРВОЕ слово значения — `APPROVED` / `PASS` / `ok`.

## 4. Конвейер

```
intake → planner → [гейт плана: человек] → qa-planner (если риск) → implementer
       → reviewer (АВТО) → qa-report (АВТО) → acceptance (АВТО, если required) → deliver (гейты человека)
```

- Автоматический переход — только по маркеру из таблицы. Ручные гейты: план → код; любой git-write
  кроме коммита; пуш, MR, мёрж; запись в трекер.
- `VERDICT: BLOCKED` / `NEEDS_CHANGES` → СТОП, не запускать следующий шаг.
- Круги ревью: не больше `pipeline.max_review_passes` (по умолчанию 3) по одному артефакту.
- `NEXT_AGENT: kit-implementer` от интейка (trivial + low + `QUESTIONS: none`) — всё равно ручной гейт:
  «делаем без плана? (да/нет)».

## 5. План (`PLAN.md`) — обязательные части

1. Фронтматтер: `task_type`, `risk: low|medium|high`, `complexity`.
2. `## Для человека` — первой секцией, ≤ 25 непустых строк. Обязательные строки:
   `Решения:` (3–5, «что выбрано — вместо чего — почему»), `Допущения:` (`A-n`),
   `Не делаем:` (`R-n OUT — почему`), `Риски:` (топ-3 по осям вариаций), `Посмотри сам:` (ОДИН вопрос,
   на который ответит только человек с контекстом бизнеса).
3. `## Реестр требований` — таблица: `R-n | фраза ТЗ дословно | IN/OUT | AC-n или причина OUT`.
   Каждая фраза ТЗ, комментария и вложения — строка реестра.
4. `## Допущения` — `A-n` с описанием.
5. `## Шаги` — `S-n`, у каждого: файлы, результат, команда проверки из конфига.
6. `## Карта двойников` — все параллельные пути того же поведения (`file:line | затронут | шаг/почему нет`)
   или фраза «grep по `<идентификаторы>` — других путей нет».
7. `## Матрица покрытия` — `AC | шаг | файлы`. AC без шага = план невалиден.
8. `## Границы` (что не трогаем) и `## Риски и откат`.

Гейт `check_gates.py --stage plan` проверяет пункты 1–3, 5, 7 механически.

## 6. QA-отчёт (`QA_REPORT.md`) — обязательные части

`## Покрытие требований` (каждый `R-n IN` → кейс), `## Матрица вариаций` (каждая ось из `qa.axes`:
кейсы или `н/п: причина`, голое «н/п» не принимается), `## Кейсы` (статусы `PASS | FAIL | SKIPPED (причина) |
INCONCLUSIVE`), `## Не проверено` (никогда не пустая), маркеры из п. 3.
Отрицательный результат без позитивного контроля тем же инструментом — `INCONCLUSIVE`.

## 7. Находки — FIX-HERE по умолчанию

- **FIX-HERE** — ≤ ~0.5 ч, та же область, не нужно решение владельца продукта → чинить в этой же задаче.
- **TICKET** — > ~1 ч / другой модуль или владелец / продуктовый выбор / миграция данных прода →
  черновик в `FOLLOWUP_DRAFT.md` с «почему не FIX-HERE»; заводится в трекере только по «да» человека.
- **NOTE** — мелочь (мёртвый код, комментарий) → строкой в описании MR.

## 8. Независимое ревью — режим «опровержение»

Независимость задаётся входом: ревьюер получает ТЗ, реестр, критерии, дифф — и НЕ получает вердикты
прошлых ревью, `STATE.md`, сводки исполнителя. Первый абзац промта ревьюера — дословно текст из
`rules/adversarial-review.md`. Находки сверяет главная сессия: `принято | контракт непонят | компромисс | шум`.

## 9. Гейты git (общие)

- Коммит — без «да», по шагам плана, только зелёное состояние, через сторож (`hooks/git-guard.sh`):
  сообщение по `git.commit_pattern`, без AI-трейлеров (если `git.forbid_ai_trailers`), индекс без
  `git.forbidden_paths`, без секретов, без файлов, изменённых после `git add`.
- Одно «да» на код = ревью диффа от merge-base → пуш в свою ветку → MR/PR.
- Всегда отдельное «да»: rebase, `--force-with-lease`, `reset --hard`, `cherry-pick`, `branch -D`,
  `commit --amend`, `merge <base>` в свою ветку, любое действие с базовой веткой.
- Никогда: `push --force`, `--no-verify`, пуш в `git.protected_branches`, `git add -A`/`.`.

## 10. Хуки kit — контракт

- Каждый хук сначала ищет `.agent-kit.yml` вверх от `cwd`. Не нашёл — молча выходит 0 (no-op).
  Поэтому хуки безопасно регистрировать и глобально.
- Отказ — JSON `permissionDecision: deny|ask` в stdout, код 0. Сбой самого хука в сторожевых местах
  (git, plan-gate) — fail-closed (deny с причиной), в напоминаниях — fail-open (молча 0).
- Никаких сетевых вызовов. Зависимости — `bash`, `python3` (3.9+), `jq`, `git`.
- `KIT_HOOKS=off` в окружении — выключить все хуки kit (аварийный обход, только по слову человека).
