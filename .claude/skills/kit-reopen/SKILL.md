# /kit-reopen — возврат задачи

Цель — понять, ПОЧЕМУ задачу вернули, раньше, чем что-то чинить. Починка без класса возврата
повторяет ту же ошибку на следующем круге.

## 1. Контекст прошлого круга (только чтение)

1. `python3 .claude/kit/scripts/state.py <KEY>` — папка, круг, ветка, воркtree.
2. Артефакты последнего круга: `TASK_CARD`, `PLAN`, `QA_PLAN`, `CHANGES`, `REVIEW`, `QA_REPORT`,
   `ACCEPTANCE`, `bugs/` — с суффиксом круга, если он есть.
3. Git: ветка задачи, влита ли она в `git.base_branch` (`git branch -r --contains`, `git log
   <remote>/<base_branch> --grep <KEY>`), что изменилось в базе с тех пор в тех же файлах.
4. Комментарий тестировщика/человека — дословно, со всеми вложениями (каждое открыть и посмотреть).
   Дописать его в `TASK.md` разделом `## Возврат rN — <дата>`. Не получено вложение — строка «не
   получено», а не догадка о содержимом.

## 2. Воспроизвести до гипотезы

- Повтори шаги тестировщика тем же способом: та же роль, данные, окружение, движок браузера (если
  баг найден не в браузере по умолчанию — воспроизводи в нём).
- Сначала на коде прошлого круга, затем на текущей базе. Внешние стенды — минимум запросов, правила
  `rules/pipeline.md`.
- Гипотеза — с фактом: file:line, вывод команды, скриншот. «Не воспроизвелось» — тоже результат:
  записать, что пробовал, и что нужно от человека (одна строка).

## 3. Класс возврата — один

| Класс | Признак | Куда смотреть в конвейере |
|---|---|---|
| не сделан пункт | фраза ТЗ потеряна или `OUT` без основания | реестр R-n карточки/плана |
| непокрытая вариация | AC выполнен, но на другом значении оси ломается | матрица QA, `qa.axes` |
| неверная трактовка | сделано, но не то, что имелось в виду | R-n и AC — формулировка |
| регрессия | сломалось соседнее поведение | карта двойников, регресс-кейсы |
| не наш дефект | причина вне задачи (данные, окружение, другая задача) | доказательство + кому передать |

Класс определяет, какой артефакт конвейера был слабым — это строка для `/kit-retro`.

## 4. Риск и круг

- Новый круг N = прошлый + 1, артефакты с суффиксом `-rN`.
- Круг 2 → риск задачи поднимается до `high` (план проверки и приёмка становятся обязательными).
- Круг ≥ 3 → СТОП до кода: подготовить для человека короткую сводку (что пробовали на каждом круге и
  почему не сработало) и предложить разговор с владельцем задачи. Код не начинать без его решения.

## 5. REOPEN_BRIEF-rN.md

`<task_dir>/REOPEN_BRIEF-rN.md`:
```
круг: rN   класс: <один из таблицы>   риск: <новый>
## Что сказали     — дословно, со ссылками на вложения
## Воспроизведение — шаги, окружение, результат, доказательства
## Гипотеза        — причина с file:line
## Что было слабым — какой артефакт прошлого круга пропустил (реестр / матрица / трактовка / карта двойников)
## Затронутое      — R-n и AC, которые меняются; новые R-n, если появились
NEXT: <одно конкретное действие>
```
NEXT — одно: «kit-intake в режиме возврата», «kit-planner: дописать PLAN-rN», «вопрос владельцу: …»,
«передать: не наш дефект — …».

## 6. Дальше

Показать человеку класс, гипотезу и NEXT (≤ 8 строк). Дальнейший путь — обычный `/kit-task` с
круга `rN`: intake (если менялись требования) → planner (план-аддендум `PLAN-rN.md`) → гейт плана.
Ветка нового круга — по `git.branch_pattern`; создание новой ветки или воркtree — обратимо, а работа в
уже влитой ветке требует решения человека.

## Никогда

Чинить до гипотезы; закрывать возврат как «не воспроизвелось» без описания попыток; писать в трекер
без «да» человека.
